# 第二轮金融 RAG：表格修复与多文档总结

本轮保留旧基线，在隔离实验中比较新检索配置；另修复正式年报模块明确点名公司但未选择其资料时的完整性判断。主平台向量库和维度不变。

## 实验设计

- 数据沿用 [FinQA 官方固定版本](https://github.com/czyssrs/FinQA/tree/0f16e2867befa6840783e58be38c9efb9229d742)，问题、答案、最小必要证据使用作者标注。仅索引公开数据包含的财报页面，不等同于完整年报全文。
- 从上一轮没有使用过的公司中，按固定 SHA256 顺序选择30家公司、每家2份报告、每报告5题。10家公司100题开发；20家公司200题保留测试。公司不跨集合；旧155题只做暴露后的回归。
- 基于作者原问题组成20道开发、40道保留测试的多文档研究总结任务，覆盖跨公司、跨年度、三报告和缺失报告。它们是构造的复合任务，不是原作者的自由总结标注或真实用户日志。
- 复合任务请求中明确给出报告和子问题；检索器只读取请求与允许的资料集合，不读取标准答案或必要证据。缺失报告仍留在请求中，但完全不进入候选集合。
- 固定4条锚点与证据预算分别评分：单报告1500 token、多报告3000 token，包含引用ID、报告和来源定位。不能把展开后的证据召回称为 Recall@4。
- 多文档报告覆盖、子问题完整证据、最差子问题召回和整体完整证据分别统计；报告覆盖不等于所需事实覆盖。40个复合任务来自10个公司对，统计时按公司对聚类。

## 改动

1. `backend/rag/table_context.py`：金额型首行不再误当表头；保留多层列头，未知列名明确编号；表格行携带同页邻近原文主题。没有读取题目或答案来构造文档。
2. 英文 embedding 对照使用本地 `BAAI/bge-small-en-v1.5` 的 Qdrant ONNX 量化发布版本（384维），与上一轮中文模型（512维）分别缓存，绝不混合向量空间。来源、revision和文件 SHA256 在 `model_manifest.json`。[BGE 模型说明](https://bge-model.com/tutorial/1_Embedding/1.2.1.html)。
3. `backend/rag/evidence_pack.py`：父表/邻近行补全、按子问题分配证据预算；共享行保留全部父表归属，不由不确定的共享行猜测父表。
4. 开发集选中英文模型＋表格上下文；单文档不强制父表展开，因为开发集没有额外召回收益。多文档选中按子问题分配预算的方案。
5. 正式 `backend/annual_reports/workflow.py`：对明确列举公司的比较请求，未选择的公司会被标记为缺少资料；不会以其他公司的证据代替，也不自动读取未选择的资料。

所有配置先在开发集冻结，再运行新测试。旧中文25题继续使用原来的 CJK 方案，不强制切换英文模型。精细重排关闭，没有训练或微调。

## 回答质量

使用此前配置的 DeepSeek，双方使用相同提示、证据预算与模型。固定抽取16道单报告数值题和12道多报告总结任务，生成模型看不到标准答案。核对作者数值、答案显示精度、可判定的单位、报告身份、最小必要引用和逐字原文引文。单位不确定时标记未评分，不能声称单位完全正确。

自由总结正文的语义完整性没有人工独立标注；逐字引文正确不等于整段推论正确。本轮主要衡量可核验事实的总结覆盖，不能把它当作通用长篇报告写作评分。

## 最终测试结果

对照“改良前”是上一轮已经优化过的 BM25/RRF 方案，而不是最初27.8%的原始版本。新旧都关闭精细重排。

| 新英文保留集，200题 | 上一轮方案 | 本轮方案 |
|---|---:|---:|
| 固定4条召回 | 64.29% | 77.59% |
| 固定4条完整证据 | 53.00% | 63.50% |
| 固定4条最小标注Precision | 25.12% | 32.62% |
| nDCG@4 | 0.5876 | 0.7398 |
| 1500-token预算内证据召回 | 86.25% | 98.08% |
| 1500-token预算内完整证据 | 76.00% | 95.00% |

固定4条召回提升13.30个百分点，按20家公司做2000次配对聚类bootstrap，95%区间约8.11–18.34个百分点。完整证据提升10.5个百分点，区间5.0–16.0。

| 消融：同一新英文测试集 | Recall@4 |
|---|---:|
| 上一轮方案 | 64.29% |
| 仅修表头 | 62.12% |
| 修表头＋表格主题，仍用中文向量 | 70.64% |
| 仅换英文向量，保留旧表格表示 | 74.22% |
| 英文向量＋正确表头＋表格主题 | 77.59% |

仅修表头虽然纠正了错误列名，却没有独立提高召回，反而在该保留集上降低2.17个百分点；不能把每项修改都说成收益。英文模型和表格主题的组合才是本轮冻结方案。

| 多文档：30道报告齐全任务，双方3000-token预算 | 上一轮全局检索 | 本轮分配子问题预算 |
|---|---:|---:|
| 必要证据召回 | 50.15% | 94.88% |
| 整题完整证据 | 20.00% | 80.00% |
| 子问题完整证据覆盖 | 47.22% | 90.56% |
| 最差子问题召回 | 21.67% | 90.56% |
| 报告出现覆盖 | 100.00% | 100.00% |

另有10道缺失报告控制题。合计40题时，仅针对可获得证据的召回为52.19%→96.16%，完整证据为22.5%→85%；这两个较高数字包含缺失报告题中较简单的可回答部分。缺失部分的拒答另行评分，不算命中。报告出现覆盖两组都100%，说明“每份报告找到一段话”不足以代表业务问题被回答。

同一英文模型＋表格主题，如果仍做单条全局查询，40题的召回为85.09%、完整证据60%；进一步按子问题分配预算才达到96.16%/85%。仅拆问题再依次填满上下文会导致首份报告占满预算，该消融只有55.86%召回，因此没有启用。

### 暴露后的旧集回归

- 原英文130题：Recall@4 58.68%→77.29%；完整证据44.62%→64.62%。这组已经用于定位问题，不能当作新的泛化证据。
- 中文25题仍使用原CJK路线，Recall@4保持87%、完整证据保持72%。没有证明新的中文收益，也没有把中文测试强行用于选择英文模型。

### 真实模型回答与总结诊断

56次DeepSeek调用，最终无HTTP/JSON/超时错误，共158,975个输入＋输出token；没有模型自评，也没有按失败样例调整提示后重跑。

| 校验项目 | 上一轮方案 | 本轮方案 |
|---|---:|---:|
| 单报告数值匹配，16题 | 5/16 | 8/16 |
| 多报告数值事实，23项有数值参考答案 | 6/23 | 11/23 |
| 多报告数值＋完整必要引用＋逐字引文，能判定的单位同时核对 | 4/23 | 6/23 |
| 缺失报告局部拒答 | 3/3 | 3/3 |
| 可完整评分的多报告题全部核验通过 | 0/11 | 0/11 |

12道多报告任务包含27个子项：24个有资料、3个缺报告。有资料子项中的1项作者答案为空，因此只有23个数值参考答案、11道能够完整评分的整题。原始报告的完整题计数分母已在独立汇总中校正；原始调用和逐项分数均保留，没有再次调用模型。

这些结果支持“检索更好、部分数值回答改善”，但不支持“复杂总结已经可靠”。一个例子是原数据把破折号编码残留写成“2014non-gaap”，模型误当成2014年；另有政府衍生品敞口需要合并两类政府数据，模型即使拿到行仍选择拒答。还有问题口径/术语、单位与计算解释需要解决。没有在本次已看过的保留集上继续调提示来包装成绩。

单位统计只覆盖模型确实作答且参考单位可判定的子项，分母会随拒答变化，不能拿条件比例宣称整体单位能力提升。逐字引文正确也不证明整段自由文本总结的语义完整性。

### 性能、验证与应用状态

- 单报告内存评测P95：9.71→12.79 ms，约增加3ms；多文档40题P95：36.17→29.99 ms。计时包含真实query embedding、检索与证据打包，部分首次collection索引；不包含离线语料向量、模型下载、LLM生成和生产数据库/并发负载。
- 所有单报告/多报告交付上下文均未超过1500/3000 token，所有多文档检索均无越过所选collection的引用。Precision基于最小gold，不是穷尽相关性判断。
- 284项年报/后端回归，加16项独立实验/评分校验，共300项不重复测试通过。涉及的正式后端与业务回归文件Ruff通过，git diff --check通过。
- 正式年报缺失公司判断已在本机8002服务生效，已对原有真实年报做API验证。英文检索配置仍保留在隔离实验中；没有切换原平台的embedding或覆盖向量库。
- 冻结后因格式检查和旧集按需缓存优化，重新验证了开发集：参数、数据和所有开发锚点指标完全一致。两次新测试逐题锚点和交付证据完全一致，最终采用最新报告计时；没有依据保留测试选新参数。
