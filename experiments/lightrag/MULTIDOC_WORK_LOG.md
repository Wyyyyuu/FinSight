# 多文档图谱增强实验记录

2026-09-15：用户要求尝试用 LightRAG 加强多文档题目。现有 Docker BGE-M3、主流程 RAG、年报数据与重排开关保持原样，本轮仅修改 experiments/lightrag 下的独立工具和结果。

- 在看到本次检索结果前，以开发集中候选语料规模最小为规则，选中 cluster3 的跨公司、跨年度、三报告任务。语料含6份报告、501个原始证据单元，包含干扰报告；不是仅索引正确答案原文。
- 所有组的模型为同一个 BGE-M3 CPU 512长度服务，最终上下文最多8个原始证据单元、3000 tokens；生成使用已配置 DeepSeek，同 prompt、温度0。实验不做精细重排，以比较图谱召回本身；线上重排仍开启。
- 逐行建图运行 `runs/20260915T060808Z-multidoc` 没有失败，但大量几十 token 的表格行逐个抽取/合并/向量化成本高，而且表格关系上下文碎片化。于任何检索/回答结果产生前主动停止，仅停止验证过身份的该实验进程；没有停 Docker 或项目服务。保留原计划、脚本快照、图索引、调用记录，并明确标记 stopped_before_retrieval。
- 修订为同报告同页聚合的78个图谱块（最多478个cl100k tokens，低于480预算）。每块保留原始source_id，回到原始行排序与8条原文引用边界。LightRAG naive 与 mix 共享同一块索引和映射规则；普通均衡与图谱辅助均衡共享子问题、表格补充和取证逻辑。索引粒度差异必须在结果中说明。
- 检索/答案产生前独立发现并记录2处标签问题：摊销比例变化缺负号、固定期限资产比例缺分子证据。只在评分器复核版本修正，原始评分保留，模型输入不含这些修正或标准答案。
- 运行入口：`experiments/lightrag/.venv/Scripts/python.exe experiments/lightrag/multidoc_pilot.py --live`；默认不带 --live 只打印设计。
- 结果入口：`multidoc_latest.json` 指向原始 report；完成后运行 `multidoc_report.py` 校验快照并生成 `MULTIDOC_RESULTS.md` 和 `multidoc_assessment.json`。

验收：全部原文映射可追溯；结果不能突破报告范围、8条原文/3000tokens；15份配对回答及逐题指标完整；不将标签Recall等同于答案准确率，不将构造的汇总题等同于真正多跳关系推理。

完成记录：聚合块运行 `runs/20260915T061925Z-multidoc` 全部78块成功，15份答案无调用错误，建图913.1秒。独立复核后保存实际执行脚本快照，并在0份答案时固定补充评分协议；后续修复可复用工具的失败答案重试、模型/评分身份校验，不改变本次加载的脚本行为。

发现等权融合将必要证据从第2位挤到第16位后，追加保留每子问题前2条基础候选的开发复测，共3次生成。排除单列的单位歧义子题后，同一6子题的数值匹配从普通均衡3/6提升到4/6；这是同开发集的调试结果，不是新盲测。等价文字与表格证据导致精确gold-ID指标低估部分正确引用，原始评分保留。最终解释见 [MULTIDOC_FINDINGS.md](MULTIDOC_FINDINGS.md)，原主流程未替换。
