# LightRAG 多文档增强：结论与复测

本次看到了局部提升，但不支持直接用 LightRAG 替换主检索。保留每个子问题的基础证据、再用图谱补充，比直接等权融合可靠。代码与索引都在独立实验中；项目原来的 BGE-M3、BM25、重排开关和年报流程没有改动。

## 测试范围

- FinQA 开发集的3道构造复合题：跨公司、跨年度、三报告汇总，共7个数值子问题。
- 6份报告（含干扰报告）、501个原文单元；LightRAG按同报告同页聚合为78块，来源ID完整保留。
- 各方案均使用 BGE-M3 CPU、同一 DeepSeek 模型/生成提示，最终最多8条原始证据、3000 tokens。实验不做精细重排，主流程的重排仍开启。
- 先完成5组共15份配对回答；发现融合问题后，在相同开发题上追加3份修复版回答。后者是看过结果后的开发调试，不是独立验证集。

## 改良方法

1. 从用户问题中明确给出的报告和子问题分别检索，使用 BGE-M3 + BM25。
2. LightRAG 从同报告同页的块索引中找实体/关系线索，把结果映射回原始证据行；生成模型不直接使用图谱摘要。
3. 每个子问题先保留普通检索的前2条候选，再补入融合后的候选，去重并按子问题均衡取证。
4. 最终统一截取8条原文，回答必须给出原文引用、单位和计算式。

保护基础候选有实际原因：在跨公司题中，一条必要原文 `F86c57bae4fb2848340` 原先排第2，等权图谱融合后掉到第16，最终被截掉。仅增加召回通道并不能保证最终上下文更好。

## 结果应如何理解

金额尺度仍有疑点的 `cross_company / facet 1` 单列：题目要求 billions，参考值为263，原文行1086与823及周边“1.1 billion”描述之间的单位转换还需要回到原PDF核验。此排除是在看到第一轮答案后提出、在修复版生成前写入修复计划，统一作用于全部方案。原始7子问题评分没有覆盖或删除。

其余6个子问题使用同一参考值（包括生成前已记录的负号修正），得到：

| 方案 | 数值匹配正确 | 说明 |
|---|---:|---|
| 普通全局 BGE-M3 + BM25 | 1/6 | 整体问题一次召回 |
| 按子问题均衡取证 | 3/6 | 本次主要基线 |
| LightRAG naive块召回 | 1/6 | 块内仍用共同的BGE-M3/BM25解析原文 |
| LightRAG mix块召回 | 1/6 | 图谱+向量，未保护基础候选 |
| 图谱等权融合后均衡取证 | 2/6 | 部分原有证据被挤掉 |
| **保留基础候选，再图谱补充** | **4/6** | 相同开发集上的修复复测 |

修复版的4个正确数值已逐项核对到实际提供的原文和计算：

- 美元债券发行额：500 + 750 + 750 = 2000（百万）。普通均衡组漏掉一笔750，回答1250；修复版补齐。
- 摊销变化：(24 − 58) / 58 × 100 = −58.62%。
- 固定期限投资占比：24704 / 25636 × 100 ≈ 96.36%。
- 欧元债券折算美元总额：1029 + 1372 + 697 = 3098（百万美元）。

另两个三报告子问题仍缺少必要数值，修复版返回无法计算。以上核对不等于整段研究总结已通过事实性审计。

## 为什么不直接使用 Recall 宣布收益

本数据既有表格行，也有同页文字中的等价内容。美元债券三笔金额和欧元债券三笔金额可从文字证据正确算出，但标准标注只列了表格行ID。因此，原先的精确ID Recall 与“引用覆盖全部gold ID”会低估这些有效证据。

例如，图谱混合组从同页三段文字算对了2000，却没有命中标注的三条表格ID。这不是凭空作答。反过来，命中标注也不能自动证明单位正确。第一轮 [完整评分](MULTIDOC_RESULTS.md) 中的 Recall 应理解为**指定证据ID的命中率**，不能当作全部可用证据的召回率或回答事实正确率。

## 成本、验证与部署决定

- 聚合块图谱建库：913秒（约15.2分钟），82次LLM调用，输入175932 / 输出81904 tokens；78块全部成功。
- 第一轮查询关键词10次LLM调用，生成15次；修复版仅追加3次生成，复用已存检索，不重新建图。
- 较早的逐行建图尝试在任何检索/答案产生前主动停止，额外102次LLM调用、215444 tokens；原记录保留，不混入修复后的耗时或效果。
- 19项离线检查覆盖来源映射、报告隔离、预算、重试、单位和保留基础候选。模型/API实测共18份答案，未出现调用失败。
- 本轮只说明这种图谱补充方式在3道开发题上有局部潜力。样本小、调试用的是同一批题、还有标注问题，不证明普遍提升，也不代表真正关系多跳场景。

部署上保留原主流程。对于当前跨财报取数问题，应继续重视表格单位、等价证据去重、必要算术输入和每个子问题的覆盖；图谱适合做可选补充，不能让它直接覆盖基础证据。

实验入口：[multidoc_pilot.py](multidoc_pilot.py)、[保留候选的修复复测](multidoc_guarded.py)。原始结果由 `multidoc_latest.json` 和 `multidoc_guarded_latest.json` 定位；第一次评分与后续修复结果分别保存。
