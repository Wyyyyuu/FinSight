# 真实金融问题：无精细重排 RAG 改良与测试

已完成公开数据构建、开发集调参、配置冻结和独立测试。新增可复用的 `backend/rag/bm25.py`，实验检索器支持 BM25、表格表头保留及按问题语言选择配置。正式 RAG 入口、生产模型配置和数据库保持原状；本轮的收益是在独立检索实验中测得的。

## 数据从哪里来

| 来源 | 本地纳入问题 | 来源与标注 |
|---|---:|---|
| [FinQA](https://github.com/czyssrs/FinQA) | 200，英文 | 真实财报问题；保留作者答案、gold_inds、公司／报告年／页面定位；MIT |
| [MultiTAT](https://github.com/zhxlia/MULTITAT) 中的 [TAT-QA](https://github.com/NExTplusplus/TAT-QA) 部分 | 37，中文 | 真实财报问题的翻译版本；通过 qid 回连原始段落标注、算式和表格行 |

原始下载来源及固定 commit、文件大小、SHA256 在 `source_manifest.json`。FinQA 论文：[Chen 等，EMNLP 2021](https://aclanthology.org/2021.emnlp-main.300/)；TAT-QA 论文：[Zhu 等，ACL 2021](https://aclanthology.org/2021.acl-long.254/)；MultiTAT 论文：[EMNLP Findings 2025](https://aclanthology.org/2025.findings-emnlp.33/)。

TAT-QA 原始数据为 CC BY 4.0。MultiTAT 仓库没有找到独立的明确许可声明，因此翻译原文和派生的 `dataset.json` 仅用于本地评测，已加入忽略列表，没有发布或提交。数据不能描述为中文原生业务日志，也不是本项目实际用户的问题记录。

MultiTAT 文件中有100条 TAT-QA 来源候选，其中98条来自 dev、2条来自 train；本次只有原始 dev 数据可回连。保留37题，排除63题：32题需要额外人工定位 span/count 证据，8题算式证据歧义，18题翻译段落结构不能一一对应，2题找不到原始 qid，3题同一上下文有冲突翻译。排除规则在检索评分前执行，保留全部排除原因。中文算式行定位是保守的自动映射，尚未完成逐题人工复核。

最终本地 `dataset.json` 包含 **237题、6037个证据片段、77个报告／上下文组**。开发集82题，保留测试集155题；英文分别70/130题，中文分别12/25题。报告／上下文组不跨集合。

FinQA 选择报告后，将该报告在公开数据中所有可用 QA 页面放入检索库，而非只放当前问题的正确页。它仍然不是完整财报全文；MultiTAT 的候选范围是原始给定上下文的全部表格行和段落。这里测的是“已知报告／上下文内的证据检索”，不包含股票识别、全库文档路由、新闻时效、权限过滤和完整 PDF 解析。

## 做了哪些改良

1. **BM25 词法检索。** 使用词项区分度、词频饱和和长度归一化，减轻常见词与长段落抢占排序的问题。组件无新增依赖，不调用 LLM，也不是 cross-encoder 重排。算法参数默认 `k1=1.2, b=0.75`，参考 [BM25 参数说明](https://www.elastic.co/docs/reference/elasticsearch/index-settings/similarity)。
2. **表格行保留表头。** 将单独的“指标｜数值｜数值”转为“指标；2019：数值；2018：数值”，支持连续多行列头。所有行使用同一序列化规则，不读取正确答案或 gold 行字符串来生成文档。
3. **开发集选择融合与语言配置。** 共20个固定候选，包含原版、CJK、BM25、表格结构及结构只用于词法的消融。以召回、完整证据和 nDCG 的均值选择，要求相对原版在各语言开发子集上不退步。按查询文本有无汉字选择配置，不能读取数据集名称、正确答案或 evidence 标签。
4. **返回证据与检索文本分开。** 数值回答补充诊断中，两组都返回带表头的原始证据；不增加候选，不改变检索排名，不使用答案补上下文。

冻结配置见 `selection.json`：英文为结构化表格 + BM25 + RRF(k=20)，词法权重1；中文保留原文 + CJK 双字召回 + RRF(k=60)，词法权重1。另保留统一 BM25 配置作对照。表头增强在开发集上并非对中文一律有效，因此没有强制统一使用同一检索表示。

## 保留测试结果

共同条件：同一真实 `BAAI/bge-small-zh-v1.5`、top-4、每问每方案3次，四组共1860次检索，无精细重排。最终证据正文不超过1500个 cl100k token。向量与词法都在相同候选集合内检索；所有数字来自冻结配置后的155题测试。

| 测试子集 | 指标 | 原版 | 冻结改良方案 |
|---|---|---:|---:|
| 英文 FinQA，130题 | Recall@4 | 27.76% | **58.68%** |
| | 完整证据命中率 | 20.77% | **44.62%** |
| | nDCG@4 | 0.2281 | **0.4747** |
| 中文 MultiTAT，25题 | Recall@4 | 83.67% | **87.00%** |
| | 完整证据命中率 | 72.00% | **72.00%** |
| | nDCG@4 | 0.8193 | **0.8549** |

| 两个数据集等权宏平均 | 原版 | 仅CJK | 统一BM25 | 冻结改良方案 |
|---|---:|---:|---:|---:|
| Recall@4 | 55.71% | 57.38% | 64.10% | **72.84%** |
| 完整证据命中率 | 46.38% | 46.38% | 52.62% | **58.31%** |
| nDCG@4 | 0.5237 | 0.5415 | 0.5861 | **0.6648** |

按全部155题直接平均，召回为36.77%→63.25%，完整证据为29.03%→49.03%；这个平均受英文样本较多影响，因此以分组结果和宏平均作为主要结论。统一BM25在中文测试上召回88%、完整命中76%，略高于冻结的中文方案，但 nDCG 略低；未据测试结果重新选择配置。

按报告／上下文做2000次配对聚类 bootstrap：英文召回提升30.92个百分点，95%区间约21.03–40.64个百分点；中文提升3.33个百分点，区间0–8.67个百分点。英文提升在本评测上较明确；中文样本小，不能声称已经证明稳定的总体召回提升。

### 性能与其他指标

- 公共内存评测器查询 P50：5.14→5.07 ms；P95：8.29→7.88 ms。计时包含每次真实 query embedding 与检索，不使用 query embedding 缓存计时，不含离线建库和答案生成。
- 使用共享向量化计算实现公平计时，并在32个开发题／模式组合上校验与项目现有检索器 top-4 完全一致；这些耗时不是原生产 Python 循环、PostgreSQL 或并发容量测试。
- 返回正文平均 token：164.18→177.96，增加约8.4%；所有条件使用相同1500正文 token 上限。
- 按最小 gold 标注计算的 Precision@4：13.55%→24.19%；这不是“真实有用内容比例”，因为作者标注不是所有相关背景的穷尽集合。
- 当前返回内容完全相同文本的重复率为0；数据构建已在报告内合并完全相同证据并保留位置别名。它不代表语义重复率为0。
- 测试中的少数题需要多于4条标注证据，固定 top-4 无法集齐，未为了提高成绩排除这些题。

### 数值回答诊断

使用现有配置的 DeepSeek 模型，固定抽取12道英文、8道中文数值题，两组配对；不让模型自评，按原作者答案做数值核对，容差固定为 `max(0.01, abs(reference)*0.001)`。该容差不覆盖所有原答案的舍入习惯；数值匹配也不等价于单位、解释、引用内容均正确。

直接使用各自检索文本时，原版5/20、改良7/20数值匹配；一次原版 JSON 格式错误单独重试后，两组均无未解决运行错误。发现缺少列头会导致“命中证据行却无法回答”，因此另做了双方统一保留表头的诊断：原版6/20（30%）、改良8/20（40%），40次调用均无运行错误。这说明证据展示本身也会影响可回答性，但样本只有20题，不能把这10个百分点当作稳定的答案质量提升。具体数值见 `answer_structured_assessment.json`；该轮是检索测试完成后的诊断，不作为一次未见数据的答案质量验收。

两种展示条件加一次格式错误重试，共81次 DeepSeek API 调用；调用及 token 明细保存在原始报告中。未执行模型训练或微调。

## 如何复现与查看

使用前一轮独立环境 `experiments/lightrag/.venv`（fastembed 0.8.0、numpy、tiktoken、httpx、pytest）。保持主环境依赖不变。

```powershell
experiments/lightrag/.venv/Scripts/python.exe experiments/financial_retrieval/fetch_sources.py
experiments/lightrag/.venv/Scripts/python.exe experiments/financial_retrieval/build_dataset.py
experiments/lightrag/.venv/Scripts/python.exe experiments/financial_retrieval/evaluate.py dev
experiments/lightrag/.venv/Scripts/python.exe experiments/financial_retrieval/evaluate.py test
experiments/lightrag/.venv/Scripts/python.exe experiments/financial_retrieval/answer_audit.py --context structured
```

前两步只下载／处理公开数据，检索评测不调用 LLM API。最后一步会使用原有实验凭据，生成40份数值回答，不输出密钥。模型缓存来自已有 `.annual-models`，缺少缓存时明确失败，不退回 hash。`evaluate.py test` 校验冻结的源码与数据 SHA256；修改数据或算法后必须重新建立独立的开发／测试实验，不能不断用同一测试集挑参数。

文件入口：

- `dataset.json`：本地问题、答案、证据、原始位置、分组和排除原因。
- `selection.json`：开发集全部候选成绩及冻结配置。
- `assessment.json`：完整分组指标、置信区间、配置与数据指纹。
- `runs/20260914T154908Z/report.json`：有效检索测试逐题结果。
- `answer_assessment.json`、`answer_structured_assessment.json`：两种证据展示条件的数值诊断。
- `backend/rag/bm25.py`：可复用词法检索与融合组件；`evaluate.py`：隔离检索实验实现。

数据复核时修正过年份后缀归一化。在结果未被查看时，旧数据版本的早期测试产物 `20260914T154629Z` 已标记 `superseded_before_results_review`，不参与上述结果。所有有效调参仍只基于开发集。

后端相关测试88项、实验与数据校验15项，共103项通过。结果证明了这个受控检索任务的改善，尚未达到之前讨论的完整证据目标，也尚未覆盖真实新闻、无法回答题、完整报告路由或生产数据库。
