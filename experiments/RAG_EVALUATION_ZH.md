# FinSight RAG 整体评估简报

日期：2026-09-15

**总体结论：当前主流程的英文检索能力明显提高；中文维持较高水平。多文档问题有所改善，但证据覆盖和数值回答仍是短板。LightRAG 已看到局部收益，目前保留为独立实验。**

## 1. 目前采用的方法

| 环节 | 当前方案 |
|---|---|
| 语义向量 | Docker 中运行真实 BGE-M3，1024维，CPU；替代此前缺少依赖时的 hash 降级向量 |
| 词法检索 | BM25，与语义向量共同召回 |
| 结果融合 | RRF，融合常数为60 |
| 召回与重排 | 先召回24条，使用 BGE-reranker-base 的 ONNX CPU 版本重排，保留8条；重排已开启 |
| 回答评测 | 使用已配置的 DeepSeek，检查数值、引用及相关单位；不把模型自评分当作事实正确率 |
| 多文档实验 | 按子问题和报告均衡取证；LightRAG 同报告同页建图，映射回原文，并尝试保留基础候选后再补充图谱证据 |

当前选用 **BGE-M3稠密向量＋BM25＋RRF**。子问题均衡取证与 LightRAG 增强尚未替换主流程；既有年报独立流程保持原样。

## 2. 主流程成效与关键数值

以下旧方案为 hash 降级向量及旧词法融合，新方案为真实 BGE-M3＋BM25；因此收益来自二者的共同改进。

| 指标与样本 | 旧方案 | 当前方案 |
|---|---:|---:|
| 英文200题：候选 Recall@24 | 77.25% | **96.67%** |
| 英文200题：重排后 Recall@8 | 72.32% | **90.02%** |
| 英文200题：全部标注证据齐备率@8 | 64.00% | **83.50%** |
| 英文200题：排序质量 nDCG@8 | 0.653 | **0.791** |
| 中文25题：重排后 Recall@8 | 97.67% | **97.67%** |
| 多文档40题：重排后 Recall@8 | 22.29% | **55.94%** |
| 单问题回答：参考数值匹配 | 9/16 | **9/16** |
| 多文档回答：参考数值匹配 | 2/14个子问题 | **6/14个子问题** |
| 英文检索＋重排耗时中位数 | 3.07秒 | **4.31秒** |

**主要收益：英文最终召回提高17.70个百分点，证据齐备率提高19.50个百分点。代价是本机CPU查询变慢；检索改善尚未等比例转化为回答正确率。** 耗时来自每组10次英文热查询，不含建库、冷启动或回答生成，不代表高并发性能。

Recall@8衡量前8条结果找回了多少标注证据，**不是答案准确率**；nDCG越高，相关证据的排序越靠前。

## 3. 多文档与 LightRAG 的实验结果

40道多文档题中，当前方案的全局 Recall@8 在重排前为61.19%，重排后为55.94%，说明整题重排会丢失部分子问题证据。改为按子问题均衡取证后，3000-token实验的标注证据召回达到 **97.54%**、齐备率达到 **90.00%**；但该方案可以保留超过8条原文，不能与固定Top8直接比较，也尚未部署。

LightRAG另测了3道复合题、6份报告、501条原文。统一最终Top8、3000-token上限，实验关闭重排；1个单位有疑点的子问题单列，其余6个子问题结果如下：

| 方案 | 数值匹配正确 |
|---|---:|
| 普通子问题均衡取证 | 3/6 |
| 图谱等权融合后均衡取证 | 2/6 |
| **保留每个子问题前2条基础候选，再由图谱补充** | **4/6** |

图谱补齐了一笔遗漏的债券记录，使一项汇总从1250修正为2000（百万）。但这是同一开发集上发现问题后的修复复测，样本很小，**不能据此宣布生产准确率达到66.7%**。聚合块图谱建库约15.2分钟，另需82次LLM调用；早期中止的逐行试运行成本另存记录。

**当前建议：继续使用已部署的 BGE-M3＋BM25＋RRF＋重排；多文档优先保障子问题覆盖、表格单位和计算输入完整性，LightRAG保留为可选增强实验。**

评估边界：现有财报评测已知报告范围，语料主要是问答相关页面，且已被实验使用过，并非全知识库盲测。标注还存在漏证据、符号/单位疑点，以及文字与表格等价证据ID不同的问题；数值或引用检查不等于整段总结的事实性评估。
